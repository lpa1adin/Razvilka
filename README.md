# Развилка

Развилка — это личная платформа, где учатся разработке на практике. Она работает у вас на компьютере
и устроена вокруг одной мысли: в программировании важно не только написать код, но и уметь объяснить,
**почему** вы сделали именно так. Каждое такое решение — «развилка», отсюда и название.

Что получает ученик:

- **теорию из проверенных источников**, а не пересказ нейросети: MDN, документация React, FastAPI и Python,
  OWASP. У каждой статьи указаны автор, лицензия и ссылка на оригинал;
- **практику с автопроверкой**: пишешь код прямо в браузере, жмёшь «Проверить» и сразу видишь, что не так;
- **тесты без повторов**: каждая попытка собирается из банка вопросов заново;
- **честную оценку решений**: независимый Ревьюер ищет дефекты в коде, а Оценщик сверяет, совпадает ли то,
  что вы *сказали* о решении, с тем, что вы *сделали* в коде;
- **разбор настоящих проектов**: проект из вашей папки раскладывается на этапы, и вы пишете его заново
  с нуля, этап за этапом.

Курсы, задания и тесты собирает Claude по вашей заявке. Вы как админ утверждаете план, проверяете
черновик и публикуете. Без вашего «да» ученик ничего не увидит.

---

## Быстрый старт

Нужен только **Docker Desktop**, он должен быть запущен.

1. Скопируйте настройки и задайте свои пароли:

   ```bash
   cp .env.example .env
   ```

   Откройте `.env` и поменяйте `RZ_ADMIN_PASSWORD`, `RZ_USER_PASSWORD` и `RZ_GRAFANA_PASSWORD`.

2. Запустите:

   ```bash
   docker compose up -d --build
   ```

   Первый запуск займёт 5–10 минут. Самое долгое — образ проверяющего сервиса с браузером Chromium (~1,5 ГБ).
   Сразу после старта сборщик скачает теорию из всех источников, это ещё пара минут.

3. Откройте **http://localhost:8660** и войдите под админом из `.env`.

| Что | Адрес |
| --- | --- |
| Платформа | http://localhost:8660 |
| Мониторинг (Grafana) | http://localhost:3060 |

Остановить — `docker compose down`, данные при этом сохранятся. Стереть всё начисто — `docker compose down -v`.

### Подключите Claude

Без Claude платформа работает: библиотека, тесты, практика и всё, что уже создано. Но наставник,
генерация курсов, Ревьюер и Оценщик ждут подключения. Claude работает на **вашей подписке**, отдельный
API-ключ не нужен.

1. Получите токен. Откроется ссылка для входа в ваш аккаунт Claude:

   ```bash
   docker compose run --rm -it --no-deps agent-worker /opt/venv/lib/python3.12/site-packages/claude_agent_sdk/_bundled/claude setup-token
   ```

2. Вставьте токен в `.env` строкой `CLAUDE_CODE_OAUTH_TOKEN=` и **замените значение целиком**.
3. Перезапустите два сервиса:

   ```bash
   docker compose up -d api agent-worker
   ```

Claude тратит лимит подписки, только когда что-то делает по вашей просьбе: строит план, пишет урок,
проверяет код, отвечает в чате. Пока ученики решают готовые задания, токены не расходуются. Расход
видно на шагах генерации и в Grafana, на панели «Токены Claude».

### Демо-контент (по желанию)

```bash
docker compose exec api python -m app.cli seed-demo-tasks   # три задания: вёрстка, Python, SQL
docker compose exec api python -m app.cli seed-quizzes      # банки вопросов по вёрстке и JavaScript
docker compose exec api python -m app.cli seed-assessment   # практикумы, рубрика Оценщика, эталонные проекты
```

## Как пользуется ученик

Меню слева разделено на «Учёбу» и, для админа, «Мастерскую».

- **Курсы.** Урок состоит из теории, теста, практики и, иногда, развилки, где надо выбрать решение и
  объяснить почему. Прогресс сохраняется.
- **Библиотека.** Все статьи источников с поиском. Читать можно и отдельно от курсов.
- **Практика:**
  - *задания* — редактор кода с живым превью, Python и SQL прямо в браузере, подсказки по одной, кнопки
    «Проверить» и «Ревью кода»;
  - *тесты* — 5–10 вопросов из банка темы, разбор ошибок со ссылками на теорию, «Повторить ошибки»;
  - *практикумы* — задача побольше: сдаёте код (zip или папку) и ответы на развилки, получаете отчёт
    Ревьюера и оценку по рубрике;
  - *тренажёр архитектуры* — 10 заданий на настоящих открытых проектах (Google Online Boutique, Sock Shop,
    шаблон FastAPI). Выбрать ответ, собрать схему, описать своими словами.
- **Мои проекты.** Путь «напиши заново сам»: настоящий проект, разложенный на этапы. Пишете в своём
  редакторе в папке `razvilka/workspace/<логин>/…`, видите превью и сдаёте этапы по порядку.
- **Развилки.** Журнал всех ваших решений с оценкой. Его можно выгрузить в `DECISIONS.md`.
- **Проверки.** История отчётов Ревьюера и оценок.
- **Наставник** — кнопка в углу любого экрана. Он знает, какой урок или задание открыто и какой код в
  редакторе. Подсказывает, но готовое решение не выдаёт. Через него же можно предложить тему для нового
  курса, и заявка уйдёт админу.

## Как работает админ (Мастерская)

### Генерация — новый курс, задания, тест или путь

1. **Заявка.** Выберите, что нужно: курс, набор заданий, банк вопросов или путь «напиши заново сам».
   Основа — тема или проект из папки `ProjectsWithClaude/`. Проект Claude видит **только на чтение**;
   файлы вроде `.env` и ключей для него закрыты.
2. **План.** Claude предлагает модули и уроки и к каждому уроку подбирает статьи из библиотеки. План можно
   править вручную или попросить «Переделать план» своими словами. Пока вы план не утвердили, ничего не
   создаётся.
3. **Черновик.** Claude пишет уроки по одному. Прямо на экране видно, что он сейчас делает и сколько это
   стоит. Если лимит подписки на исходе, нажмите **«Пауза после урока»** или **«Остановить сейчас»**,
   а после сброса лимита — **«Продолжить»**. Готовые уроки не теряются.
4. **Автопроверки.** Каждое задание проверяется без участия Claude: эталонное решение обязано проходить
   тесты, а стартовый код — нет. Если что-то не сходится, Claude один раз чинит задание по отчёту.
5. **Ревью эталона.** Независимый Ревьюер проверяет эталонное решение и тесты (подробнее ниже). Если он
   нашёл серьёзные замечания, Claude сам исправляет эталон, до двух раундов.
6. **Ваша проверка.** У каждого урока видно теорию, задание, результат автопроверки и отчёт Ревьюера.
   Нажмите на строку «Ревьюер», чтобы увидеть каждое замечание с кодом. Не нравится урок —
   «Переделать урок» с пояснением.
7. **«Опубликовать всё».** Публикуется всё сразу или ничего, если где-то остались проблемы. Список проблем
   покажется.

### Контент

Редакторы курсов, заданий и банков вопросов. Всё хранится **версиями**: правка опубликованного создаёт
черновик, ученики видят старую версию, пока вы не опубликуете новую.

- **Задание.** Условие, стартовый код, эталон, тесты, подсказки, статьи. «Проверить задание» запускает
  автопроверку. В отчёте Ревьюера есть кнопка **«Исправить по замечаниям»**. Если Claude, исправляя
  эталон, захочет поменять условие или стартовый код, правка не применится сама: вверху редактора появится
  блок «Было / Станет» с кнопками «Принять» и «Отклонить».
- **Тест.** Тест — это 5–10 случайных вопросов из банка темы. Банк — 20–50 вопросов, тогда попытки почти
  не повторяются. Если вопросов мало, кнопка **«Дописать вопросы»** добавит недостающие по статьям темы.
  Новые вопросы приходят черновиками, без повторов.

### Источники

Список источников теории, их лицензии и история импорта. Сборщик обновляет источники раз в неделю.
Кнопка «Импортировать сейчас» запускает обновление сразу. Если в источнике изменился файл лицензии, импорт
остановится, пока вы не прочитаете лицензию и не подтвердите её здесь же.

### Оценивание

- **Правила Ревьюера** — версии, у каждого правила есть источник (OWASP, WCAG, PEP 8, руководства Google…).
  Правила можно включать, выключать и редактировать. Каждый отчёт помнит, по какой версии проверяли.
  Кнопка «reviewer.md» выгружает те же правила как агента для Claude Code.
- **Рубрика Оценщика, эталонные проекты, практикумы, все сдачи** учеников.

### Пользователи и Система

Учётки и роли. «Система» показывает, живы ли сервисы и подключён ли Claude.
Пользователя можно создать и из консоли:

```bash
docker compose exec api python -m app.cli create-user anna --role user --name "Анна"
```

## Насколько можно доверять проверке

Чтобы оценки были честными, устроено так:

- **Ревьюер независим по контексту.** Каждый раз он запускается в новой сессии, без инструментов. Видит
  только условие, код и правила, а не переписку с наставником. Адрес каждого замечания (файл, строку,
  правило) проверяет сама платформа, вердикт тоже считает она.
- **Тесты тоже на ревью.** Правило TEST-02 требует, чтобы автотесты проверяли каждый критерий условия и
  проваливались на неверном решении.
- **Второй взгляд другой моделью.** Эталон считается чистым, только если его отдельно пропустила ещё и
  вторая модель (Claude Sonnet): у неё другие слепые пятна.
- **Условие не подгоняется под код.** Исправляя эталон, Claude может менять только эталон и тесты, причём
  тесты нельзя удалять. Всё остальное идёт вам на одобрение.

Чего это **не** гарантирует: ревью — работа модели, и повторный прогон может найти что-то новое.
«Замечаний нет» значит «серьёзных проблем не найдено», а не «ошибок нет». Поэтому финальное слово всегда
за вами.

## Как добавить источник теории

Источники добавляются **только в коде**, через белый список. Это сделано специально: так вы точно знаете,
откуда берётся теория и на каких условиях её можно показывать.

Сейчас подключены:

| Источник | Язык | Лицензия | Как показывается |
| --- | --- | --- | --- |
| MDN Web Docs | рус. | CC BY-SA 2.5 | полный текст |
| learn.javascript.ru | рус. | разрешение автора | только оглавление и ссылка |
| Документация React | рус. | CC BY 4.0 | полный текст |
| Документация FastAPI | рус. | MIT | полный текст, примеры кода из репозитория |
| Документация Python | англ. | PSF License 2 | полный текст |
| OWASP Cheat Sheet Series | англ. | CC BY-SA 4.0 | полный текст |

### Шаги

1. **Проверьте лицензию.** Источник должен лежать в открытом git-репозитории. Найдите файл лицензии и
   прочитайте его:
   - открытая лицензия (CC BY, CC BY-SA, MIT…) — можно показывать полный текст (`full_text`);
   - лицензия запрещает копирование — только название, оглавление и ссылка (`reference`).

2. **Добавьте запись** в `backend/app/modules/library/sources.py`, в словарь `SOURCES`:

   ```python
   SourceSpec(
       slug="vue-ru",                                  # короткое имя латиницей
       title="Документация Vue",                       # как увидит ученик
       author="Команда Vue и участники",
       kind="docs",                                    # docs | tutorial | book | course
       homepage="https://ru.vuejs.org/",
       license_name="MIT",
       license_url="https://github.com/…/LICENSE",
       license_mode=LicenseMode.full_text,             # или LicenseMode.reference
       license_note="Что изменено при показе и чьи права — ученик увидит это под статьёй.",
       repo="https://github.com/…",                    # откуда клонировать
       patterns=("/LICENSE", "/docs/**/*.md"),         # какие файлы брать (картинки не нужны)
       license_file="LICENSE",
       license_marker="MIT License",                   # строка, которая обязана быть в лицензии
       parser="vue",                                   # каким разборщиком читать статьи
   ),
   ```

   `license_marker` — страховка. Если владелец источника сменит лицензию, этой строки в файле не станет,
   и импорт остановится, пока вы не разберётесь.

3. **Разборщик.** Если источник в обычном Markdown с заголовком `# Название`, возьмите за образец
   `parse_owasp`. Если в нём свои компоненты или вставки, как у React и FastAPI, нужна своя функция в
   `backend/app/modules/library/parsers.py` и строчка `elif spec.parser == "…"` в
   `backend/app/modules/library/importer.py`. Разборщик отдаёт название, ссылку на оригинал, HTML (он
   очищается автоматически), оглавление и текст для поиска.

4. **Проверьте и запустите:**

   ```bash
   docker compose build && docker compose up -d
   ```

   Сборщик сам заметит новый источник и импортирует его. Результат появится в Мастерской → Источники
   (сколько статей добавлено) и в Библиотеке.

## Настройки

Всё задаётся в `.env`. Основное:

| Переменная | Что значит | По умолчанию |
| --- | --- | --- |
| `RZ_ADMIN_LOGIN`, `RZ_ADMIN_PASSWORD` | первый админ (создаётся при первом запуске) | — |
| `RZ_USER_LOGIN`, `RZ_USER_PASSWORD` | первый ученик | — |
| `CLAUDE_CODE_OAUTH_TOKEN` | токен подписки Claude | пусто — Claude выключен |
| `RZ_WEB_PORT` | порт платформы | 8660 |
| `RZ_GRAFANA_PORT`, `RZ_GRAFANA_PASSWORD` | мониторинг | 3060 |
| `RZ_IMPORT_EVERY_DAYS` | как часто обновлять источники | 7 |
| `RZ_AGENT_MODEL` | модель для кода: исправление эталона, Ревьюер, Оценщик | `claude-opus-5-5` |
| `RZ_TEXT_MODEL` | модель для текста: план, уроки, вопросы, чат наставника | `claude-sonnet-5-5` |
| `RZ_REVIEWER_SECOND_MODEL` | модель второго взгляда на эталоны | `claude-sonnet-5-5` |
| `RZ_AGENT_TIMEOUT_SECONDS` | сколько ждать один ответ Claude, прежде чем прервать | 1200 |
| `RZ_SESSION_DAYS` | сколько живёт вход | 14 |

После правки `.env` перезапустите сервисы: `docker compose up -d`.

## Git и секреты

Всё личное хранится в `.env`: токен подписки, пароли, порты. Этот файл внесён в `.gitignore`, поэтому
в репозиторий он не попадает. Тот, кто скачает проект, получит `.env.example` с заглушками и подключит
свою подписку сам. Код учеников из `workspace/` тоже не коммитится.

После клонирования один раз включите проверку перед коммитом. Она не даст случайно закоммитить `.env`,
ключи и токены:

```bash
git config core.hooksPath .githooks
```

Полезное:

- посмотреть историю — `git log --oneline`;
- вернуть файл к прошлой версии — `git restore --source <коммит> <файл>`;
- отменить последний коммит, оставив изменения в файлах, — `git reset --soft HEAD~1`.

## Если что-то не работает

- **«Claude не подключён».** В `.env` нет токена, или вы не перезапустили `api` и `agent-worker` после
  того, как его добавили.
- **«Исчерпан лимит подписки Claude. Сбросится в …».** Дождитесь указанного времени и нажмите «Продолжить
  черновик» или «Продолжить» на экране заявки. Всё готовое сохранено.
- **«Claude не ответил за 20 мин».** Вызов завис и был прерван, чтобы не держать очередь. Просто повторите шаг.
- **Превью задания пустое во встроенном браузере Claude.** Это особенность встроенного браузера: он не
  запускает скрипты в изолированных окнах. В Chrome, Safari и Firefox превью работает.
- **«Python не загрузился».** При первом запуске браузер качает ~12 МБ для Python, обновите страницу.
- **Что сейчас в работе и что ждёт решения** — одной командой: `docker compose exec api python -m app.cli status`.
- **Перезапуск не тратит лимит сам.** Если воркер перезапустился посреди работы Claude, задача не возобновится
  сама: генерация встанет на паузу («Продолжить» на экране заявки), исправление нужно запустить заново.
- **Что-то странное с сервисами.** Загляните в Мастерскую → Система или в логи:
  `docker compose logs -f agent-worker`.

Платформа рассчитана на запуск у себя на компьютере. Прежде чем выставлять её в интернет, нужны HTTPS,
`RZ_COOKIE_SECURE=true`, другие пароли Postgres и Grafana и ограничение попыток входа.

## Для разработчика

```bash
docker compose up -d                        # бэкенд, база и воркеры
cd frontend && npm install && npm run dev   # интерфейс с горячей перезагрузкой: http://localhost:5190
```

Тесты бэкенда (у них отдельная база):

```bash
docker compose build api && docker compose run --rm --no-deps api pytest -q
```

Новая миграция после изменения моделей:

```bash
docker compose run --rm --no-deps -v "$PWD/backend/alembic/versions:/srv/alembic/versions" api alembic revision --autogenerate -m "что изменилось"
```

Коротко об устройстве: бэкенд на FastAPI и Postgres, интерфейс на React. Тяжёлую работу делают отдельные
воркеры: `agent-worker` (Claude), `collector` (импорт теории) и `runner` (автопроверки, без доступа в
интернет). Очередь задач хранится прямо в Postgres.

Подробности:

- [docs/BRIEF.md](docs/BRIEF.md) — техническое задание;
- [docs/DECISIONS.md](docs/DECISIONS.md) — почему сделано так, а не иначе (архитектурные решения);
- [docs/REVIEWER.md](docs/REVIEWER.md) — правила Ревьюера с источниками.
