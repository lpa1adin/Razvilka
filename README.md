# Развилка

Локальная платформа практического обучения разработке: теория из проверенных источников, тесты без
повторов, песочница с автопроверкой, тренажёр архитектуры, разбор своих проектов «напиши заново сам»
и Claude, который собирает курсы (в Мастерской админа) и независимо оценивает решения.

**Статус:** готовы все этапы 0–8.
- **Этап 0** — вход, роли пользователь/админ, меню «Учёба ⇄ Мастерская», все сервисы в Docker, мониторинг.
- **Этап 1** — библиотека (MDN ru — полный текст, learn.javascript.ru — оглавление и ссылка), поиск,
  курсы с уроками, прогресс; в Мастерской — редактор курсов с черновиками и версиями, источники, пользователи.
- **Этап 3** — тесты: банк вопросов по темам (один ответ, несколько, порядок, сопоставление, вопросы с кодом),
  10 вопросов без повторов от попытки к попытке, продолжение прерванного теста, разбор ошибок со ссылками
  на теорию, «Повторить ошибки»; в Мастерской — редактор банка с проверкой на дубли; тест в уроке.
  Банки: «Вёрстка: семантика HTML, CSS и Flexbox» (50 вопросов) и «JavaScript: сравнения и типы» (8).
- **Этап 2** — практика: песочница (Monaco + живое превью / Python / SQL прямо в браузере), «Проверить»,
  подсказки, автосохранение; в Мастерской — редактор заданий и автопроверка в runner (Chromium);
  задания встраиваются в уроки. Три демо-задания: шапка сайта, функция на Python, SQL-запрос.
- **Этап 4** — Мастерская → Генерация: заявка (проект из `ProjectsWithClaude/` или тема) → план от наставника
  (правится, переставляется, «Переделать план») → черновик по урокам (теория из библиотеки, задание, вопросы)
  → автопроверки в runner (не прошло — Claude один раз чинит по отчёту) → проверка админом
  («Переделать урок») → «Опубликовать всё». Чат-наставник на любом экране учёбы: знает урок, задание
  и код в редакторе, отвечает потоком, готовое решение не выдаёт, подсказки считаются в попытке;
  «Предложить тему» отправляет заявку админу.
- **Этап 5** — независимый Ревьюер: «Ревью кода» в песочнице (замечания с правилом, строкой и сценарием,
  клик — переход к строке), раздел «Проверки» с историей; ревью эталона — обязательная автопроверка перед
  публикацией задания; правила версиями в Мастерской → Оценивание; агент для Claude Code
  (`.claude/agents/reviewer.md`, команда `python -m app.cli export-reviewer`).
- **Этап 6** — сдачи и Оценщик: практикумы (Практика → Практикумы) с развилками в формате ADR; сдача zip
  или папкой проекта; конвейер автотесты → Ревьюер → Оценщик; отчёт с блоком «сказал ≠ сделал» (цитата
  ответа рядом со строкой кода), баллы по рубрике, ответ эталона после оценки; журнал «Развилки» с выгрузкой
  в DECISIONS.md; в Мастерской — рубрика версиями, эталоны, практикумы, все сдачи.
- **Этап 7** — тренажёр архитектуры (Практика → Тренажёр архитектуры): 10 заданий на реальных открытых
  проектах (Online Boutique, Sock Shop, full-stack FastAPI, сама Развилка) — выбрать → собрать схему из
  блоков → описать своими словами (оценивает Claude); после ответа — разбор и авто-схема, построенная по файлу.
- **Этап 8** — разбор проектов «напиши заново сам» (Мои проекты): админ строит путь по папке из ProjectsWithClaude
  (Генерация → «путь»), этапы проверяются тестами на оригинале; ученик пишет проект с нуля в
  `razvilka/workspace/<логин>/<путь>/` в своём редакторе, видит превью и сдаёт этапы по порядку — автотесты,
  Ревьюер, Оценщик; ответ автора на развилки — после оценки.

Разделы следующих этапов показывают честную заглушку.

- [docs/BRIEF.md](docs/BRIEF.md) — техническое задание и план этапов (§9)
- [docs/DECISIONS.md](docs/DECISIONS.md) — архитектурные развилки (ADR)
- [docs/REVIEWER.md](docs/REVIEWER.md) — правила независимого ревьюера

## Запуск

Нужен запущенный Docker Desktop.

```bash
cp .env.example .env   # один раз; задайте свои пароли
docker compose up -d --build
```

| Что | Адрес |
| --- | --- |
| Платформа | http://localhost:8660 |
| Grafana (дашборд «Развилка — сервисы») | http://localhost:3060 |
| Prometheus | http://localhost:9090 |

Учётки админа и пользователя создаются при первом запуске из `RZ_ADMIN_*` и `RZ_USER_*` в `.env`.
Остальные — в Мастерской → Пользователи или командой:

```bash
docker compose exec api python -m app.cli create-user anna --role user --name "Анна"
```

Демо-задания (создаются черновиками; потом в Мастерской → Контент → Задания: «Проверить задание» → «Опубликовать»):

```bash
docker compose exec api python -m app.cli seed-demo-tasks
```

Банки вопросов для тестов (публикуются сразу; вопрос без найденной статьи-источника остаётся черновиком):

```bash
docker compose exec api python -m app.cli seed-quizzes
```

### Claude (наставник и генерация)

Работает через Claude Agent SDK на вашей подписке (ADR-007). Нужен токен — выпустите его один раз
(откроется ссылка для входа в аккаунт Claude):

```bash
docker compose run --rm -it --no-deps agent-worker /opt/venv/lib/python3.12/site-packages/claude_agent_sdk/_bundled/claude setup-token
```

Вставьте выданный токен в `.env` строкой `CLAUDE_CODE_OAUTH_TOKEN=…` и перезапустите:

```bash
docker compose up -d api agent-worker
```

Проект агент видит через граф (`backend/app/modules/projectmap/graph.py`, ADR-018): карта в несколько КБ
вместо чтения всех файлов. Расход токенов — в Grafana (панель «Токены Claude») и в шагах генерации;
в простое Claude не вызывается.

Без токена всё остальное работает, а наставник и генерация честно пишут, что Claude не подключён.
Токен видят только `api` (чтобы показать статус) и `agent-worker`; в `runner` и `collector` он пустой.
Проекты из `ProjectsWithClaude/` подключены к `agent-worker` только на чтение; агенту доступны Read и Glob
внутри выбранного проекта, файлы вроде `.env` и ключей закрыты.

Практикумы, рубрика Оценщика и эталонные проекты (этап 6):

```bash
docker compose exec api python -m app.cli seed-assessment
```

Первая сборка дольше обычного: образ `runner` содержит Chromium (~1,5 ГБ).

Остановить: `docker compose down` (данные остаются в томах). Стереть всё: `docker compose down -v`.

## Разработка

```bash
docker compose up -d                        # API, БД и воркеры
cd frontend && npm install && npm run dev   # интерфейс с горячей перезагрузкой: http://localhost:5190
```

Vite проксирует `/api` в контейнер `web`, так что вход и данные — те же.

Тесты бэкенда (отдельная БД `razvilka_test`):

```bash
docker compose build api && docker compose run --rm --no-deps api pytest -q
```

Новая миграция после изменения моделей:

```bash
docker compose run --rm --no-deps -v "$PWD/backend/alembic/versions:/srv/alembic/versions" api alembic revision --autogenerate -m "что изменилось"
```

## Как устроено

Модульный монолит (ADR-001): один код бэкенда, четыре процесса.

```
                 127.0.0.1:8660
браузер ──► web (nginx: SPA + /api) ──► api (FastAPI) ──┐
                                                        ├──► postgres (данные, очередь задач, сессии)
            agent-worker  ─ Claude (этап 4) ────────────┤
            collector     ─ импорт теории (этап 1) ─────┤
            runner        ─ проверки, БЕЗ интернета ────┘
prometheus ──► собирает /metrics со всех ──► grafana :3060
```

- Сеть `internal` закрыта от интернета: в ней `postgres` и `runner`. Остальным сервисам нужен выход наружу
  (Claude, источники), поэтому они подключены и к `public`.
- Очередь задач — таблица `jobs` в Postgres, `SELECT … FOR UPDATE SKIP LOCKED` (ADR-004).
- Права проверяет сервер: все маршруты `/api/workshop/*` закрыты `require_admin`, пользователь получает 403.
- Сборщик при первом запуске сам импортирует оба источника (около минуты), потом обновляет их раз в неделю.
  Копии репозиториев — в томе `sources`. Белый список и лицензии — `backend/app/modules/library/sources.py`.
- Практика (ADR-006, ADR-015): песочница работает в браузере — iframe `/sandbox.html` без доступа к
  платформе и Pyodide в отдельном потоке. Автопроверку задания перед публикацией делает `runner`
  теми же файлами проверок (`backend/app/modules/practice/harness/`).
- Курс хранится версиями-снимками (ADR-013): правка опубликованного создаёт черновик новой версии,
  пользователи остаются на своей версии и видят предложение перейти.

## Адаптив

- **≥ 1024 px:** боковое меню, сворачивается до иконок (запоминается).
- **< 1024 px:** верхняя панель и меню-шторка (закрывается по Esc и по клику мимо).
- Проверено на 375 / 768 / 1280 / 1440. Анимации выключаются при `prefers-reduced-motion`.

## Перед публикацией в интернет

Сейчас всё рассчитано на локальный запуск. Для сервера: HTTPS и `RZ_COOKIE_SECURE=true`, сменить пароли
Postgres и Grafana, выключить анонимный доступ к Grafana, ограничение попыток входа.

## Если что-то не работает

- **«Claude не подключён» / «исчерпан лимит подписки».** Нет токена в `.env` или закончился лимит — см.
  раздел «Claude» выше. Упавший шаг генерации повторяется кнопкой на экране заявки, готовые уроки не теряются.

- **Превью рабочей папки пути пустое во встроенном браузере Claude** — та же причина, что ниже: изолированный
  iframe. В обычном браузере работает (проверено в Chromium).
- **Превью веб-задания пустое во встроенном браузере Claude.** Его панель не выполняет скрипты
  в изолированных (sandbox) iframe. В обычных Chrome, Safari и Firefox всё работает — это проверено
  в Chromium сквозным сценарием.
- **«Python не загрузился».** Первый запуск качает около 12 МБ из `/pyodide/`; обновите страницу.
