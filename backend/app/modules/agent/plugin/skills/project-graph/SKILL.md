# Граф проекта

Платформа заранее строит граф проекта без участия модели: файлы, связи между ними (HTML → CSS/JS,
импорты), каркас страниц, заголовки, id и классы, правила CSS и медиазапросы, функции, классы и константы
JS/Python, что ищет JS на странице, какие классы стилизованы, но не используются. Библиотеки (vendor,
*.min.*) в граф не входят — их не читать.

## Порядок работы

1. **Сначала граф.** Карта проекта уже лежит в задании (раздел «Карта проекта»). Если её там нет —
   вызвать `project_map`. Этого хватает, чтобы понять устройство и составить план.
2. **Оглавление файла — вместо чтения.** Нужны подробности одного файла (все функции, все классы,
   все медиазапросы) — `project_file` с путём. Это в разы дешевле, чем Read.
3. **Read — только за точными строками.** Читать файл, только когда нужна конкретная цитата кода:
   пример для задания, точное значение свойства, текст разметки. Читать частями (offset/limit),
   а не целиком, если файл длиннее 200 строк.
4. **Не перечитывать.** Один и тот же файл не открывать дважды; не искать файлы через Glob —
   их список уже в графе.

## Чего не делать

- Не читать файлы подряд «чтобы понять проект» — граф для этого и построен.
- Не открывать библиотеки и минифицированные файлы.
- Не выдумывать файлы, классы и функции, которых нет в графе.
